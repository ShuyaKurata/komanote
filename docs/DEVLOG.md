  - サブツール: Gペン / 丸ペン / カブラペン / ミリペン / 鉛筆 / シャープペンシル / ラフ鉛筆 / 筆 / ベタ塗り用 / エアブラシ / 消しゴム3種

- キーボードショートカットは一般的なペイントソフトに合わせた(P ペン、E 消しゴム、[ ] でサイズ、⌘Z など)

### 動作確認
- ブラウザで新規作成 → 描画 → 取り消し → 自動保存 → 再読み込みで内容が戻ることを確認

## 2026-11-16 コマ割り(`feature/panel-layout`)

### やったこと
- **コマ枠ツール**(K キー)を追加。サブツールは 3 つ
  - コマ枠カット: 線を引くと、その線が通るコマを 2 つに分ける。斜めの線でも分けられる
  - 長方形コマ: ドラッグでコマを作る
  - コマ枠の編集: コマを選んで移動・頂点を動かす・削除(Delete キー)
- **コマの間隔は自動**: 横向きの線で分けると「上下の間隔」、縦向きの線だと「左右の間隔」(初期値 5mm / 2mm)
- 線の角度を水平・垂直・45° に吸着する(オン/オフ可)
- **テンプレート**: 1コマ / 2段 / 3段 / 4段(4コマ) / 田の字 / 3段・中段2分割。新規作成時に選ぶと、後から追加したページにも使われる
- ツールプロパティで枠線の太さ・間隔を mm 単位で変更できる
- **コマの外側を白で隠す**: コマからはみ出した絵を隠す(オフにすれば枠外にも描ける)
- レイヤーパレットの一番上に「コマ枠」の行(表示/非表示、コマ数)
- コマの変更も取り消し/やり直しできる

### 判断したこと
- コマは「多角形の頂点リスト」で持つ。分割は半平面で凸多角形を切る方法(Sutherland–Hodgman)で行い、
  分割線から間隔の半分ずつずらした 2 つの半平面で切ることで、すき間を作っている
- コマ枠はラスターレイヤーの上に描く(絵の上に枠線が乗る)。コマごとにレイヤーフォルダでマスクする方式は
  操作が複雑になるので見送り、ページ全体で「コマの外側を白で隠す」方式にした

### 動作確認
- 新規作成(1コマテンプレート)→ 水平に分割 → 上段を斜めに分割 → 再読み込みで 3 コマが残ることを確認

## 2026-11-16 テキスト・フキダシ(`feature/text-balloon`)

### やったこと
- **テキストツール**(T キー): タップした位置に文字を置く。既存の文字をタップすると編集
- **フキダシツール**(F キー): 楕円 / 角丸 / ナレーション(長方形) / 思考(雲) / 叫び(トゲ)。
  タップで標準サイズ、ドラッグで好きな大きさに作れる。「しっぽを付ける」はフキダシの中から引っぱる
- **操作ツール**(O キー): テキスト・フキダシを選択して移動、四隅で拡大縮小、オレンジの点でしっぽを移動。
  選択中のものをもう一度タップすると文字を編集。Delete で削除、前面/背面へ
- 選択中のフキダシはツールプロパティから、フォント・文字サイズ(pt)・縦書き・太字・行間・白フチ・文字色・形・線の太さ・しっぽの太さを変えられる
- **縦書き組版**: 列は右から左、長音や「…」・括弧は 90° 回転、句読点は右上、小さい「っゃゅょ」は少し右上、
  2 桁の数字や「!?」は縦中横(1 マスに横並び)
- **アンチック風フォント**: 漫画のセリフでよく使う「かなは明朝、漢字はゴシック」を文字ごとにフォントを切り替えて再現
- レイヤーパレットに「テキスト・フキダシ」の行(表示/非表示)

### 判断したこと
- フキダシとしっぽは「2 倍の太さで線を描く → 白で塗る」の順で描き、本体としっぽの継ぎ目を消している
  (パスを結合すると回転方向によって重なり部分が抜けることがあるため)
- 文字を変えるとフキダシの大きさを自動で合わせる。手でサイズを変えたら自動調整をやめる(「文字に合わせる」で戻せる)
- スライダーで連続して変えたときは、止まってから 1 回だけ取り消し履歴に積む(`editor.live()`)

### 動作確認
- 楕円フキダシに 2 行のセリフ(「!?」「…」「っ」を含む)を入れ、縦書き・縦中横・アンチック風で表示されることを確認

## 2026-11-17 塗りつぶし・トーン・選択範囲・効果線(`feature/fill-tone-effects`)

### やったこと
- **塗りつぶしツール**(G キー)
  - 他レイヤーを参照: 見えている絵・コマ枠・フキダシを境界にして塗る(線画レイヤーと塗りレイヤーを分けられる)
  - 編集レイヤーのみ参照 / 囲って塗る(投げ縄で囲んだ範囲を塗る)
  - 色の誤差・領域拡縮(線との境目の隙間を埋める)
  - **トーン(網点)**: 線数・濃度・角度を指定。網点はページの原点にそろえるので、何度貼っても点がずれない
- **選択範囲ツール**(M キー): 長方形 / 投げ縄。選択中はペン・塗りが選択範囲内だけに効く
  - キャンバス上部に「選択解除 / 消去 / 塗りつぶし / トーン / 変形」のバーを表示
  - 「トーン」は新しいレイヤーを作ってそこに網点を貼る
- **変形**(⌘T): 選択範囲(なければレイヤーの描いてある範囲)を移動・拡大縮小・回転・反転。Enter で確定、Esc でキャンセル
- **図形・効果線ツール**(U キー): 直線 / 長方形 / 楕円 / **集中線** / **流線**
  - 集中線: 中心からドラッグして空白部分の大きさを決める。本数・線の太さ・ばらつきを設定できる
  - 効果線は、選択範囲 → 押した位置のコマ → ページ全体 の順に描く範囲を決める(コマの中で使うとコマからはみ出さない)

### 判断したこと
- 塗りつぶしはスキャンライン方式。B5・200dpi(約 350 万画素)で実用的な速さ
- 変形中は元の画素をレイヤーから切り取り、表示のときだけ変形した画像を重ねる。確定時にレイヤーへ描き込み、
  変形前のレイヤー全体を取り消し用に持っておく
- 塗り方の設定(線数・濃度・角度)はサブツールごとに覚える。メニューの「選択範囲にトーンを貼る」は「トーン(網点)を貼る」サブツールの設定を使う

### 動作確認
- 下段のコマに集中線を描き、コマ内に収まることを確認
- 上段左のコマをトーンで塗り、コマ枠で止まることを確認
- 長方形選択 → 変形 → 移動 → Enter で確定 → 取り消しで元に戻ることを確認

## 2026-11-17 書き出し・PWA 対応・iPad 縦向きの調整(`feature/export-pwa`)

### やったこと
- **書き出し**(ファイル → 画像・PDF の書き出し、⇧⌘E、コマンドバーの「書き出し」)
  - 形式: PNG / JPEG / PDF。ページ: このページ / 全ページ
  - 出力範囲: キャンバス全体 / 裁ち落としまで(入稿向け) / 仕上がりサイズ(Web 向け)
  - 全ページの PNG/JPEG は ZIP にまとめる。下書きレイヤーとガイドは書き出さない
  - iPad では共有シート(「ファイルに保存」など)にも渡せる
- **作品ファイル(.komanote)**: レイヤーの画素を含めた 1 ファイルで保存・読み込み(バックアップ・別端末への移動用)
- **PWA**: `manifest.webmanifest`・アプリアイコン・`sw.js` を追加。ホーム画面に追加すると全画面で起動し、オフラインでも動く
- **iPad 縦向き**: 幅が狭いときはパレットを最初から隠す。選択中のツールをもう一度タップで開き、キャンバスに触れると閉じる
- README を最新の機能・使い方・ショートカットに更新

### 判断したこと
- PDF と ZIP は外部ライブラリを使わず最小限の形式を自前で組み立てた(PDF は各ページに JPEG を 1 枚貼る形)。
  PDF のページサイズは出力範囲の実寸(mm → pt)にしてある
- Service Worker は「ネットワーク優先、失敗したらキャッシュ」。更新がすぐ反映され、オフラインでも起動できる
- 開いていないページを書き出すときは、そのページのレイヤーだけを一時的に読み込んで、終わったら解放する

### 動作確認
- PDF・ZIP を生成し、PDF は macOS で開けること(sips で PNG に変換できること)、ZIP は Python の zipfile で読めることを確認
- 画面から「PDF・このページ・仕上がりサイズ」で書き出し → 完了ダイアログ(712KB)まで確認
- 作品ファイルを作って読み込み → コマ 3 つ・フキダシ 1 つ・レイヤー画素が復元されることを確認
- iPad 縦向き相当(820×1180)でパレットが隠れ、キャンバスが全面に表示されることを確認

## 2026-11-17 iPad で線を描くと重い問題の修正(`fix/drawing-performance`, v1.1.0)

### 症状
iPad で全体的に重く、特に線を描いているときにカクつく。

### 原因(計測して特定)
1. **線を描くたびに原稿全体を描き直していた。** 全レイヤー(B5・200dpi で 1 枚約 350 万画素)・コマ枠・フキダシをフレームごとに描画していた
2. **ペンの入力 1 点ごとにレイヤーを合成し直していた。** Apple Pencil は 1 秒に最大 240 点届くので、1 フレームに何度も合成が走っていた
3. **縦書きのフキダシを毎フレーム 1 文字ずつ組み直していた。** 描画時間の約 3 割
4. 線を描き終えるたびに、取り消し用データを `getImageData`(GPU からの読み戻し)で取っていた。iPad では手を離した瞬間に引っかかる
5. 描いている途中でもサムネイル更新や自動保存(PNG への変換)が走ることがあった

### やったこと
- **描画中は変わった部分だけ描き直す**: 描き始めに「編集中レイヤーより下」と「上(コマ枠・フキダシ・ガイド含む)」を画面サイズの画像にしておき、
  描画中は変更範囲だけ「下の画像 + 編集中レイヤー + 上の画像」を重ねる(`editor.beginStrokeView` / `renderStrokeDelta`)
- **レイヤーへの合成はフレームごとに 1 回**: ブラシの点はバッファにためて、表示の直前にまとめて合成(`StrokeEngine.flush`)
- **フキダシは画像キャッシュ**: 内容が変わったときだけ描き直し、普段は画像を貼るだけ(拡大表示中は文字をきれいに見せるため直接描画)
- **取り消し用データは小さなキャンバスへのコピー**で取り、手が空いたときに ImageData へ変換(iOS はキャンバス用メモリの上限が小さいので長くは持たない)
- **ブラシの丸いカーソルを別のキャンバスに分けた**: Pencil をかざして動かしても原稿を描き直さない
- 座標変換の逆行列とキャンバスの位置をキャッシュ(入力イベントごとの計算を減らした)
- 描いている間はサムネイル更新と自動保存を後回しにする。自動保存は手を止めて 4 秒後
- Service Worker を `no-cache` で取りに行くようにし、更新がすぐ iPad に届くようにした。ホーム画面にバージョン(v1.1.0)を表示

### 計測結果
GPU の処理時間はこの開発環境のブラウザでは正確に測れないため、キャンバスを CPU 描画に切り替えて同じ処理の時間を比べた
(iPad のような遅い環境に近い条件)。フキダシ 9 個のページで、線を描いている間の 1 フレームあたり:

| | 修正前 | 修正後 |
| --- | --- | --- |
| 平均 | 10.2ms | 1.2ms |
| 最大 | 20.9ms | 3.9ms |

### 動作確認
- 擬似的な Pencil 入力で線を描き、取り消し/やり直しで画素が完全に元に戻ること(ImageData への変換前・変換後の両方)を確認
- マウスで線を描き、表示が崩れないことを確認
- 途中で、カーソル描画の関数を消してしまっていたバグに気づいて修正済み

## 2026-11-17 データの保存についての注意書きとバックアップ導線(`feature/storage-notice`, v1.2.0)

### 背景

そのことを利用者が分かるようにしてほしい、という要望。

### やったこと

  - 端末の保存領域の使用量と、永続化(消されにくい保存)が有効かどうかを表示
- 見られる場所: 初回起動時に 1 回自動表示 / 作品一覧の上の注意書き(「詳しく」)/ 作品一覧の「保存について」ボタン /
  エディタの「ヘルプ → データの保存について」/ 操作方法ダイアログの先頭
- 作品一覧の各作品に **「バックアップ」ボタン**(作品を開かずに作品ファイルを書き出せる)
- バックアップ日時を記録し、一覧に「✓ バックアップ済み」「⚠ 未バックアップの変更あり」「⚠ まだバックアップしていません」を表示
  - 書き出し完了ダイアログで「ダウンロード」か「共有・ファイルに保存」を選んだときだけ、バックアップ済みとして記録する
- README に「仕組み(処理と保存の場所)」と「データの保存について」を追記

### 判断したこと
- バックアップ日時は作品データ本体ではなく localStorage に記録する。作品データに書くと「更新日時 > バックアップ日時」の比較がずれるため
- 処理はすべて端末側で、サーバー(GitHub Pages)は静的ファイルを配るだけ。利用者が増えてもサーバー側の負荷は配信量だけで、
  一度開けば Service Worker のキャッシュから起動するので配信量も小さい

- バックアップ → 完了ダイアログで「閉じる」を選んだ場合は未バックアップのままになることを確認

## 2026-11-17 保存まわりの見直し: ファイル連動と作品一覧の整理(`feature/file-link`, v1.3.0)

## 2026-11-17 Google ドライブ同期(`feature/google-drive-sync`, v1.4.0)

### 背景
iPad の Safari はローカルファイルとの連動(🔗)に対応していないため、iPad でも自動でファイルに残せるよう Google ドライブと同期したい、という要望。

### やったこと
- **Google ドライブで同期 ☁**(`js/gdrive.js`, `js/drive-ui.js`, `js/filelink.js`)
  - 作品の ⓘ → 「Google ドライブで同期」/ エディタの「ファイル → Google ドライブで同期」で、ドライブの「コマノート」フォルダに作品ファイルを作る
  - 以後は自動保存のあと(手が止まって 15 秒後・作品を閉じるとき・アプリを離れるとき)にドライブのファイルも上書き
  - 作品一覧の「☁ Google ドライブ」で、ドライブにある作品の一覧と「開く」(別の端末で続きを描ける)
  - 作品を開くとき、ドライブの方が新しければ(他の端末で更新された)、ドライブの版を読み込むか選べる
  - 他の端末で更新されたファイルは上書きせず、「(競合 日時)」付きの別名で保存し、以後はそちらと同期する
  - ドライブ上の名前(競合コピーなど)は保ち、作品名を変えたときだけファイル名も変える
  - ログインの期限(約 1 時間)が切れたら、右上の状態表示が「☁ 要ログイン」になり、押すとログインし直して保存する
  - クライアント ID が未設定なら、作り方の手順と入力欄を出す(`js/config.js` に書けば全員が使える)
- 作品一覧のマークは、ファイル連動が 🔗、ドライブ同期が ☁。「データの保存について」と README にドライブ同期の説明と初期設定の手順を追加

### 判断したこと
- **サーバーを置かない。** Google Identity Services のトークン方式で、ブラウザだけでログインする。リフレッシュトークンは使えないので、
  1 時間ごとにユーザーの操作でトークンを取り直す(ポップアップはタップ直後でないと開けないため、自動では取り直さない)
- **権限は `drive.file` だけ。** このアプリが作った・開いたファイルしか触れないので、ドライブ全体を見る権限より安全で、Google の審査も軽い
- ホーム画面アプリ(iPad)ではログインのポップアップが開けない場合があるので、そのときはページ移動でログインする方式(リダイレクト)に切り替えられるようにした
- 同期の単位は作品ファイル 1 つ(全レイヤー入り)。差分アップロードではないので大きい作品では時間がかかるが、仕組みが単純で壊れにくい

### 動作確認
本物の Google ログインにはクライアント ID が必要なため、ページ内に偽の Google ドライブ(API の応答を返すもの)を作って確認した。
- 同期開始でフォルダとファイルが作られる / 編集 → 保存でドライブのファイルが更新され、状態表示が「保存済み ☁」になる
- ドライブ側が他の端末で更新されていると、上書きせず競合コピーが作られ、元のファイルは変わらない
- トークン切れで「☁ 要ログイン」(押せる表示)になる
- ドライブ側が新しいことを検出し、ドライブの版で端末の作品を置き換えられる
- ドライブの作品を開くと読み込まれて同期状態になり、もう一度開くと同じ作品が開く(二重に読み込まない)
- 競合コピーの名前が次の同期で元の名前に戻ってしまう不具合を見つけて修正
